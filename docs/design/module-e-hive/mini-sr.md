## 一、验收标准（怎样算做完）

| 编号 | 验收项 | 验证方式 | 优先级 |

## 二、技术风险点

| 风险编号 | 风险描述 | 可能性 | 影响 | 应对方案 |
|----------|----------|--------|------|----------|
| R-01 | 进化阈值调参不当导致系统失衡 | 中 | 高 | 提供默认配置 + 暴露调参接口 |
| R-02 | 虫巢意识网广播导致性能瓶颈 | 中 | 中 | 实现分层缓存机制 |
| R-03 | 战功评估算法不公平引起用户不满 | 低 | 中 | 结合显式反馈 + 可解释性报告 |
| R-04 | 基因库格式兼容性（未来升级） | 低 | 中 | 版本化存储 + 迁移脚本 |
| R-05 | 多线程/异步竞争条件 | 中 | 高 | 核心状态加锁 + 单元测试覆盖 |

## 三、平台能力边界确认

| 能力 | 确认结果 | 备注 |
|------|----------|------|
| Python asyncio 支持复杂状态机 | ✅ 可行 | 使用 asyncio.Lock 保护共享状态 |
| Pydantic 可序列化复杂嵌套模型 | ✅ 可行 | 战功记录、基因种子均可 Pydantic 化 |
| FastAPI WebSocket 支持广播 | ✅ 可行 | 可用于虫巢状态同步 |
| 本地文件系统存储基因库 | ✅ 可行 | YAML/JSON 格式，< 10MB 无压力 |
| SQLite 存储战功记录 | ✅ 可行 | 可选，当前先用 JSON |
| 跨进程 Agent 通信 | ⚠️ 后续 | Phase 1 先用线程级，后续考虑 multiprocessing |

## 五、最小可用定义（MVP 范围）

**Phase 1 必须实现：**

```
主脑 × 1（全局单例）
├─ 小主脑 × N（每 Thread 一个）
│  ├─ 刀虫（代码执行）
│  ├─ 枪虫（信息搜集）
│  └─ 脑虫（分析审查）
├─ 虫巢意识网（上下文共享）
├─ 战功记录（JSON 存储）
└─ 进化引擎（规则判断）
```

**Phase 1 不实现：**
- 工蜂群（Rippers）聚合
- 宿主（Hosts）容器化
- 复杂晋升路径（只实现刀虫→脑虫）
- 基因种子优化算法

## 六、顾问建议的 Phase 划分

参考 `gpt-des.md` 的 Phase 计划，当前 Module E 可按以下阶段推进：

| Phase | 范围 | 验收标志 | 依赖 |
|-------|------|----------|------|
| **E0** | 接口锁定 | ContextPacket, BroodTask, MemoryScope, HandoffDigest 类型定义稳定 | 无 |
| **E1** | 最小虫群基础 | Overmind + 1 Submind + 1 Host + BroodTask 生命周期 | E0 |
| **E2** | 多 Host 执行 | 多 Host 类型 + 审查门 + 优先级调度 | E1 |
| **E3** | 进化层 | GeneCandidate + TrialBrood + 晋升降级 | E2 |
| **E4** | 长期记忆升级 | 向量检索 + SQLite 持久化 | E3 |

**当前建议进入 Phase E0**，先锁定接口，避免后续重构。
